# CircleCI Android APK

CircleCI is the fast APK-build path for Nyla. The existing GitHub Actions workflows stay available and unchanged.

The CircleCI workflow is intentionally dormant on normal pushes. It only starts the expensive Android build when the pipeline parameter `build_apk` is explicitly set to `true`.

## One-time environment setup

Open **CircleCI → Nyla project → Project Settings → Environment Variables** and add these six values:

```text
CLOUDFLARE_API_TOKEN
CLOUDFLARE_ACCOUNT_ID
ANDROID_KEYSTORE_BASE64
ANDROID_KEYSTORE_PASSWORD
ANDROID_KEY_ALIAS
ANDROID_KEY_PASSWORD
```

Use exactly the same values as the GitHub Actions release setup.

`ANDROID_KEYSTORE_BASE64` is the permanent signing keystore generated by Nyla's **Generate Android Keystore** GitHub workflow. Do not create a second signing key for CircleCI.

There is no `NYLA_SYNC_BASE_URL` environment variable. The CircleCI job resolves the existing `workers.dev` address from the Cloudflare account and embeds it in the APK automatically.

## Build an APK

In CircleCI, trigger a new pipeline for `main` and add these pipeline parameters:

```text
build_apk        boolean  true
release_version  string   1.0.0
deploy_sync      boolean  false
```

`build_apk=true` is the switch that actually runs the Android job.

Use `deploy_sync=false` for normal UI/device builds. The APK still targets Nyla's current sync service, but CircleCI does not redeploy it.

Use `deploy_sync=true` when you intentionally want this pipeline to deploy the encrypted sync Worker after all app and relay validation passes.

## What the job does

The job:

1. validates all six environment variables;
2. installs the pinned Flutter 3.44.9 toolchain with caching;
3. resolves Nyla's Cloudflare sync address;
4. regenerates the pinned Android/iOS scaffolds and applies Nyla's native configuration;
5. renders and installs the Nyla launcher artwork;
6. restores the permanent Android signing key;
7. generates Drift code;
8. runs strict Flutter analysis and all app, cycle-engine, sync-core and health-content tests;
9. typechecks and tests the encrypted sync relay;
10. builds the signed release APK;
11. verifies the APK signature and writes a SHA-256 checksum;
12. optionally deploys and health-checks the sync Worker.

## Get the APK

Open the finished CircleCI `release-apk` job and open **Artifacts**.

The build publishes:

```text
Nyla-<version>.apk
Nyla-<version>.apk.sha256
```

The GitHub **Release APK** workflow is still present as the production/GitHub-release path. CircleCI is an additional build path, not a replacement.
